# 対象外のセンサー監査と比較範囲

## 実測した不一致

本家2.7.1の固定コーパスには、42個の `audit.md` に106ブロックが含まれる。旧版の同42ファイルは70ブロックで、新版には `SENSOR_FIRED` / `SENSOR_PASSED` / `SENSOR_FAILED` の36ブロックが加わっている。汎用の監査ブロック描画は106ブロックすべてを再現できた。

一方、`projection_golden_test` を新コーパスへ移すと、gate開始・修正後の再提示でセンサー由来の行がなく一致しない。`report/awaiting-approval` と `report/revised` の監査原本に存在する。採取元や既存の期待バイトは変更していない。

[契約C1](../../../inception/contract-design/contract-summary.md) は選定した観測を原則として全文比較し、未知の差を失敗とする。[C3](../../../inception/contract-design/contract-summary.md) と利用者の対象外指定はセンサーの製品実装を除外している。この境界を独断で比較から落とさず確認する。

## Q1: センサー由来の監査を今回どう扱うか

A. 対象外として明示する（推奨）。今回のnative互換判定では上記3種類のセンサー監査行だけを対象外とし、それ以外の監査・状態・標準出力・標準エラー・終了値の比較を維持する。元の106ブロックを保存し、汎用描画テストでは全ブロックを検査する。センサー行が一致した、あるいはセンサー機能を実装したとは報告しない。

B. センサー監査も全文一致のまま要求する。実際の発火・成功・失敗に対応した監査を生成する機能が必要になるため、対象外指定と作業範囲を改めて調整する。架空のセンサー実行記録は生成しない。

[Answer]: A. 対象外として明示する

利用者の回答原文: 「推奨」。直前に提示した「3点すべて推奨案で再開する」を選択した回答として記録する。

## 独立して修正する差

`Validation Basis`、`Source Baseline`、`Skip Kind`、ジャンプ時の成果物無効化情報の欠落はセンサー監査の除外案に含めない。これらを同じ例外で落とさず、必要な保存事実と投影を実装する。今回の状態投影テストは18件中9件成功・9件失敗であり、移行完了とは扱わない。
