# 稼働記録の保存失敗に対する診断出力

## 実測した境界

固定本家2.7.1 `a277af218f0df7f325d3b8be7b6d90fce2c5bd40` の `aidlc-write-audit-log.ts` は、JSON入力の解釈より先に稼働記録を保存する。記録先の `.aidlc-hooks-health/write-audit-log.last` がディレクトリの場合、Bun 1.3.13の実行結果は次のとおりだった。

- 終了コード1、標準出力は空、公開ファイルの変更なし。
- 標準エラーに `EISDIR: illegal operation on a directory, open '<対象パス>'` と、path/syscall/errno/codeの診断情報がある。
- さらに、TypeScriptのソース抜粋、スタックトレース、`Bun v1.3.13 (macOS arm64)` の処理系情報が付く。

入力・ディレクトリ配置・全出力の生バイトは `tests/golden/selfhost-stage1/write-audit-health.json` の `heartbeat-directory/1` に保存済み。

## 裁定が必要な理由

[契約C1](../../../inception/contract-design/contract-summary.md) は標準エラーも既定でバイト比較し、未知の差を失敗とする。既存の正規化は実測した環境依存値に限られるため、Bunの診断構造をRust側の出力へ読み替える変更は未承認である。利用者の「上流仕様と現行コードが食い違ったら、読み替えず人間に裁定を求める」という指定に従い、この1ケースの扱いを確認する。

## Q1: この保存失敗の診断出力をどう比較するか

A. 処理系固有の診断を別扱いにする（推奨）。終了コード1、空の標準出力、エラー種別 `EISDIR`、操作 `open`、対象パス、公開ファイルの副作用は本家と一致させる。Rustの標準エラーは次の1行と末尾LFに固定する。Bunが付けるソース抜粋・構造化診断・スタック・処理系版名は、そのまま保存した観測証拠として残し、このケースのRust出力とは全文比較しない。

```text
EISDIR: illegal operation on a directory, open '<対象パス>'
```

この扱いは `write-audit-log` の稼働記録先がディレクトリである場合に限定する。他のエラー、固定の業務文言、監査語彙、終了値、状態や監査の変化へ一般化しない。対象パスには既存の対称なパス正規化だけを適用する。Rustの固定出力と本家のエラー種別・操作・対象パスをそれぞれ検査し、標準エラー全体を無条件に無視しない。

B. 現行の全文比較を維持する。処理系が付ける診断も含めて本家と一致する出力を実装対象とする。差を隠す正規化は追加しない。

[Answer]: A. 処理系固有の診断を別扱いにする

利用者の回答原文: 「推奨でいいよ」。2026-09-09（日本時間）に上記の1ケース限定の扱いを承認した。他の診断出力へ例外を広げない。
