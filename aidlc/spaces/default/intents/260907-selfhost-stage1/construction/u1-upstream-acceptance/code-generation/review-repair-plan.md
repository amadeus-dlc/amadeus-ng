# U1レビュー指摘の是正

第1回レビューのR-01〜R-03を、承認済み計画の比較・CI・自動検査の責任範囲で修正する。指摘の原文と判定は[計画末尾のReview](code-generation-plan.md#review)を保持する。

| 指摘 | 実装する修正 | 先に失敗を確認する検証 |
| --- | --- | --- |
| R-01 | 生観測のinitial_files・changed_files・fixture_changesを、損失のないバイト列として比較する。正しいUTF-8だけに文字列の正規化を適用する | FFとFEの異なる1バイトを各ファイル面に保存し、両辺seal後の比較CLIが差を検出する。既存のstdout/stderrとID対応の検出も保つ |
| R-02 | CIで、Bun検査の前に固定本家コミットを利用できるよう取得条件を整える | fork tipだけをdepth1で取得した隔離環境では現状git archiveが128で失敗すること、修正した準備で固定元の実バイトを取得できることを確認 |
| R-03 | code-generationの自動検査で、権威ある単位割当から対象FRを決める。配布変更は同期パッチにする | U1のFR1範囲を正しく認識し、未割当FRの混入と担当FRの欠落を検出する。ゼロUnit・既存US・他単位の検査も保つ |

期待する対象範囲を、検査されるtraceability.json自身から推測してはならない。要求書や割当表を検査の都合で変えず、架空のシナリオID・対応ファイルを追加しない。

変更対象は比較器と回帰テスト、CI設定、traceabilityセンサーの同期パッチ・配布3本と回帰テスト、同期台帳、およびU1の実測記録・source-manifestである。必要な実装差分を1件ずつRed→Green→Refactorで進め、保存コーパス・独立再採取の比較・同期・関連テストを再検証した後、第2回の独立レビューを受ける。

## 再承認が必要になった理由

第1回レビューの追記で計画ファイルの内容が変わり、正規verifyはapproved:trueでもfingerprintValid:false・receiptValid:falseを返した。自動承認保護が修正作業を拒否したため、新しいCode Generationの指示を取得し、現在の計画・テスト手順・Testing Contractの指紋を質問ファイルへ記録し直した。既存の承認受領を書き換えて再利用していない。

現在、指摘3件へのソース修正は未着手。番号回答の抽出不具合は別途修正・検証済みで、今回の確認には番号を使用できる。
