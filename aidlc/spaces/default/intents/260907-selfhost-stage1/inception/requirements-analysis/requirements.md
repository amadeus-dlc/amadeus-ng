# stage-1 セルフホスト切替の要求

## 目的と範囲

amadeus-ng自身で本リポジトリの開発を進められる状態に切り替える。Claude Code上で、小さなbugfixの作業を開始から人間の承認を経て完了まで通すことを中心に、現バイナリに欠ける経路だけを追加する。[desc]

互換対象は**本家2.7.1**である。既存ゴールデンの2.6.40据え置きという初回の解釈は利用者の訂正で撤回した。ゴールデン（本家から採取する比較用データ）、テストの参照先・検証内容、実装を2.7.1仕様へ揃える。[Q1]

状態・監査・承認受領を更新する処理はRustに統一する。更新を伴わない配布補助処理は、読取り互換と副作用を確認して再利用する。既存コードの再文書化は行わず、実地スモークに必要なコード解析資料だけを例外として生成する。[Q2][Q3]

## 機能要求

すべて今回の必須要求とする。正常な操作と拒否・失敗の両方を、指定した境界で検証する。

### FR1: 本家2.7.1へ受入基準と実装を揃える

本家固定コミットから配布データと実行結果を再採取し、既存のCLI・フック・状態/監査投影・正規化/ハッシュ等の受入検証を2.7.1の契約へ移行する。採取元・環境・手順・比較で除外する非決定値を記録する。旧期待値を現在の互換性の根拠として使い続けない。[Q1][M1][M4]

- **正常時**: 2.7.1から採取した入力を実装へ与えると、対象契約の終了コード、標準出力・標準エラー、状態・監査の差分が一致する。固定文字列、フィールド、配置と列挙値は本家の観測契約に従う。
- **不一致時**: 新旧差分、既存テストのキー集合比較、既知の欠落・未検証ケースを区別して示す。実装を修正するか、人間の裁定を受けるまで該当する互換条件を達成扱いしない。採取結果の手修正、比較項目の削除、正規化の拡大で差を隠さない。

### FR2: Claudeから作業の開始・質問・承認・完了へ到達する

本リポジトリでreleaseバイナリの`next / continue / report`と作業開始の入口が連携し、実地スモーク用の新しいintent（1件の開発作業記録）を完了まで進められること。配布手順が実際に呼ぶ入口をRustへ接続し、同じ状態を別の実装で並行更新しない。[desc][Q2][M2]

- **正常時**: CLIから渡した要求、環境と必要なカーソル観測が実処理へ届き、質問待ち・承認待ちでは停止し、人の回答後に正しい段階へ進む。終了条件が満たされたときだけ完了になる。
- **拒否時**: 不正な継続トークン、誤った段階・古い回答・承認のない前進を本家の対象契約に従って拒否する。拒否によって承認済みや完了済みに変化しない。
- **範囲限定**: `NextTurnInput`の未接続観測を一律に実装せず、Claudeの選定経路と自己診断で使うものを対象にする。Kiro専用ラッチ等は対象外。

### FR3: 必要なフックと承認受領をRustで成立させる

主要4フックである停止制御、人間の応答記録、状態遷移の保護、ファイル保存時の監査を実装する。手順で必要な`decision / answer / link / review`と、内容確認・実装計画承認の受領も成立させる。[desc][Q2][M2][M3]

- **正常時**: 実際のClaudeの発火入力から、必要な人間応答・資料保存・引継ぎ・レビュー・承認の事実が記録され、対応する操作だけが先へ進める。セッションに結び付いた実装計画の許可は、監査行だけで代替しない。
- **拒否時**: 回答前、別セッション、対象や内容の変更後、直接の状態遷移、古い資料・受領の再利用を、本家の選定契約に従って検出する。停止制御は正当な質問待ちを妨げず、再入・進捗のない繰返しも本家の境界どおり扱う。
- **追加登録の扱い**: 配布設定にある実装計画承認保護、レビュー保護、開始・終了・状態同期等についても、スモークで発火する経路と正本への書込みを分類する。主要4本以外だから無検証で残すことや、すべてを無条件に移植することはしない。

### FR4: 正本を更新する処理と再利用する補助処理を分離する

スモークで呼ぶ処理を、Rustへ接続する更新処理と、再利用できる更新しない補助処理に分類し、呼出し一覧に対応を記録する。`learnings persist`、資料管理の監査、実行許可の発行なども、名称によらず実際の副作用で判定する。[Q2][M2]

- **正常時**: 再利用する表示・指紋計算等が、Rustが投影した状態・監査・規則・資料を正しく読み、本家の対象契約に合う結果を返す。
- **境界の検証**: 更新しないと分類した操作の前後で、状態・監査・承認受領等の正本に変更がないことを確かめる。更新する操作を別コマンドで提供する同一TypeScriptファイルも、操作単位で扱う。
- **不適合時**: 正本の更新や読取り不整合が判明した操作は再利用対象に含めず、必要なRust実装・接続へ回す。SQLiteの書込みとファイル投影を既存の永続化・投影経路に沿って扱い、別系統の状態を作らない。

### FR5: bugfixとfeatureの配布資産を利用できる

自プロジェクトの開発で使うbugfix/feature相当のステージ・役割・プロトコル・グラフを、配布元の資産で揃える。ステージ本文の独自作成は行わず、本リポジトリ固有の接続変更は同期パッチとして管理する。[desc][Q1][Q2]

- **正常時**: 両スコープの定義から必要なステージと参照資産が解決でき、選定したbugfix一周がその資産を使う。今回、feature全工程の実地実行までは要求しない。
- **欠落時**: 必要資産の欠落・不整合を診断し、架空の資料や空の成功結果で補わない。

### FR6: このリポジトリの切替に必要な自己診断を提供する

`target/release/aidlc --doctor`が、バイナリの入口と必要なClaudeフックの配線、bugfix/featureの配布資産、ワークスペースの状態・監査・永続化の整合を検査できること。対象外の機能を成功項目として数えない。[desc][Q2]

- **正常時**: 本リポジトリの切替構成について必要項目が成功し、検査結果と終了状態から利用可否を判定できる。
- **異常時**: 必要な入口・資産・フックの欠落や、選定した状態/監査の破損を検出し、問題の箇所を示す。診断が状態・監査を勝手に修復・再初期化しない。
- **詳細化**: 本家2.7.1の各診断項目と、今回採用する項目・対象外理由の対応、および正常/異常の出力契約を契約設計で固定する。

### FR7: 本リポジトリ上の実地スモークを完了する

小さなbugfix相当のintentを1本、`target/release/aidlc`を作業進行の実体として、開始 → 質問 → 人間のゲート承認 → 完了まで通す。本リポジトリとClaude Code、実フック、人の応答を用いる。[desc][Q3]

- **成功証拠**: 対象コミット、使用したバイナリの識別、呼出し、回答・承認・完了の状態/監査、自己診断、CI結果を作業記録から追えること。
- **代替不可**: `runtime::run`を繰り返す統合テスト、試験装置による人間応答の注入、承認保護の無効化を実地成功の代わりにしない。拒否が起きた場合も、迂回して成功扱いしない。
- **資料の限定例外**: このスモークに限り、配布bugfix手順が要求するコード解析資料と引継ぎを生成する。小さな修正の関係箇所を主な調査対象とし、浅い確認を深い解析済みと表示しない。今回の開発計画全体で既存コードの再文書化を再開する許可にはしない。

### FR8: 検証済みの版をホストとして切り替える

実地スモーク、自己診断、CI全ジョブ成功を確認した版を安定タグで識別し、ホストを直近の安定タグ、ターゲットを開発版として使い分ける。[desc]

- **正常時**: どの実体で作業を進め、どの実体を開発しているかを識別できる。安定タグと検証対象コミットが対応する。
- **失敗時**: 開発版の不具合により進行できなくなった場合、検証済みホストを使える。具体的な参照先・切替手順・復帰条件は実行計画と切替工程で確認し、未検証の版を安定版と呼ばない。

## 非機能要求

- **NFR1: 観測互換** — FR1の対象契約について、ワークスペース配置、状態ファイル形式、監査イベント語彙、固定文言を本家2.7.1と照合する。内部のSQLiteイベントソーシングと投影方式を再設計しない。[desc][Q1]
- **NFR2: 品質基準の維持** — TDDのred → green → refactor、workspace行カバレッジ床90.0%と既存相対ゲート、Quint/ITF、fmt・clippy・独自lint・単体/統合検証を維持する。既存テストの成功と実地スモークは別々に示す。[desc][practices]
- **NFR3: CIの全結果確認** — 対象コミットと起動イベントに対して全ジョブを確認する。依存監査は現在の集約対象外でも今回の成功条件に含める。元のイベント条件で非適用になる検査は成功に書き換えず、適用理由を記録する。失敗を残したまま統合・切替を完了しない。[desc][practices]
- **NFR4: 調査・変更の限定** — 現コードと配布資産を根拠に、必須経路で使う差分だけを変更する。会話・説明は日本語、術語は初出で説明し、観測契約の固定文字列は逐語で保持する。[desc][Q2][Q3]

## 制約と対象外

- [承認済み開発規則](../practices-discovery/team-practices.md)と、`aidlc/spaces/default/knowledge/aidlc-shared/coding-rules/README.md`の正本・衝突優先順を適用する。上流と現コードの差を独断で読み替えない。
- Boltごとに [Pull Request](https://github.com/amadeus-dlc/amadeus-ng/pulls) を1本、直列・squash-mergeで統合し、CIとレビュー収束を条件にする。ここでは新規の起票・マージ・タグ作成を行わない。
- ステージ定義は配布資産を再利用し、独自変更は同期パッチへ記録する。手書きの文書ツリーをリポジトリ直下に新設しない。
- 自律実行、センサー・プラグイン・他ハーネス、配布一般化、OTel、インストーラ、仕様12/13号の全文執筆、スモークで踏まない既存課題は対象外。未接続のCLI操作を全部実装することも要求しない。
- 既存コードの再設計・再文書化は対象外。FR7で人間が認めたスモーク用の必須解析資料のみ例外とする。
