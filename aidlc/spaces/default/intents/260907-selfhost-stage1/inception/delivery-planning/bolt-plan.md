# セルフホスト切替の実行計画

## 進め方と統合単位

Bolt（実装・検証・統合までのまとまり）を3つ設け、B1 → B2 → B3の順で直列に進める。各Boltを [Pull Request](https://github.com/amadeus-dlc/amadeus-ng/pulls) 1本とし、CI全ジョブ成功とレビュー収束を確認してmainへsquash-mergeする。[Q1]

単位の依存関係は[承認済みDAG](../units-generation/unit-of-work-dependency.md)を維持する。単位ごとに実装計画・TDD・検証を完了して次へ進むが、U1単独では統合せず、U2と併せてB1を完成させる。並列実装、自律実行、独立した先行実装は設けない。

| 順 | Bolt | Unit ID / Directory | 統合で確認すること |
| --- | --- | --- | --- |
| 1 | B1: 2.7.1の受入基盤と作業進行 | U1 / u1-upstream-acceptance、U2 / u2-workflow-authority | 本家2.7.1の採取基準・対応実装・検証内容が揃う |
| 2 | B2: セルフホスト用の自己診断 | U3 / u3-selfhost-doctor | C7の採用診断と正常/異常の外部契約を満たす |
| 3 | B3: 配布接続・切替準備 | U4 / u4-selfhost-integration | 実配布接続、補助処理の副作用、実地実行と復帰の準備が揃う |

## B1: 2.7.1の受入基盤と作業進行

### 内容

- U1で本家固定コミット`a277af218f0df7f325d3b8be7b6d90fce2c5bd40`から採取し、来歴・非決定値・比較対象と差分を明示する。
- U2で必要なCLI・フック・質問/回答/引継ぎ/レビュー/実装許可をRustへ接続し、既存実装とテストの参照先・検証内容を2.7.1へ移行する。
- reportの更新ユースケースは`Result<(), E>`に揃える。集約のイベントをSQLiteへ追記し、RMUの投影後に報告識別子で結果をクエリする。旧い成功戻り値経路とその正当化を残さない。
- 状態・監査・承認受領を更新する操作をRustへ統一する。C7の診断実施の記録も、U3が利用する更新契約としてU2が所有する。
- この作業記録、専用スコープ、利用者が是正を指示した自動検査の同期パッチ・回帰テストも、作業の前提として引き継ぐ。本製品へセンサー機能を追加した成果とは数えない。

### 完了条件

- [ ] 採取元の完全SHAと実行環境が固定され、必要な2.7.1の比較データが揃っている。
- [ ] 対象実装と対応テストが2.7.1の契約に一致する。旧2.6.40の期待値を現行受入の根拠として残していない。
- [ ] 正常・拒否・古い受領・対象変更・別セッション・投影失敗・報告結果の取り違えを検証した。
- [ ] 更新コマンド、イベント、Repository、RMU、Queryの責任が分離され、CQSの例外や別の成功戻り値経路がない。
- [ ] 必要なローカル検証とCI全ジョブが成功し、対応すべきレビュー指摘と競合が解消している。

**この統合で確かめること**: 採取基準と実装を同時に揃え、作業進行・承認の事実をRustで管理できる。デモはreleaseバイナリの対象CLI/フック境界検証と、報告イベントから結果を取得する経路とする。Claude上の人間承認を含む最終実地スモークの完了とは区別する。

## B2: セルフホスト用の自己診断

### 内容

U3で契約C7のD1.a–D5.bを実装し、DC1–DC10の正常/異常、非適用、助言、stdout/stderr、終了状態、診断監査を検証する。Queryは読取り専用とし、診断事実の記録は外側からU2の別コマンドへ渡す。

### 完了条件

- [ ] 本家対応の診断項目と独自の必須診断を区別している。
- [ ] 初回状態を壊れた既存記録と混同せず、評価不能を成功へ丸めない。
- [ ] 必須失敗は終了1、助言だけなら終了0とし、非適用項目を成功数へ加えていない。
- [ ] 初回は記録を新規生成せず、既存監査がある場合はC7どおり診断実施を記録する。
- [ ] 異常ケースを含む検証とCI全ジョブが成功し、レビューが収束している。

**この統合で確かめること**: セルフホストに必要な構成の不足を診断できる。デモは正しい構成と故意に不足させた構成の診断結果の対比とする。B3で接続する実環境の最終診断は後続で確認する。

## B3: 配布接続・切替準備

### 内容

U4で配布手順からRustと再利用補助処理へ接続し、必要な同期パッチ・統合検証・スモーク実行準備を整える。ホストと開発版を識別し、検証済みホストへ戻せる方法を準備する。

### 完了条件

- [ ] bugfix/featureの必要な配布資産と参照先が解決する。
- [ ] 実際に呼ばれる更新処理はRustへ接続し、TypeScriptとの二重更新や失敗時の別実装への切替がない。
- [ ] 再利用する補助処理の読取り互換と、正本を更新しないことを検証した。
- [ ] 本リポジトリで実地スモークする小さな修正・記録・バイナリの選択を具体化し、現在の開発記録を壊さない方法を用意した。
- [ ] ホスト版・開発版の識別、切替・復帰の方法が確認可能で、関連検証とCI全ジョブが成功し、レビューが収束している。

**この統合で確かめること**: 配布手順とRustの実入口がつながり、実地確認を実行できる。準備のデモは接続・診断・バイナリ識別の検証とし、実際の切替済みとは呼ばない。

## 共通の検証・統合条件

実装前に現行の検証結果を取り、各変更をTDDで進める。次の現行検査と、各Boltが追加する対象テストを維持する。

| 検査 | 現行の実行入口 |
| --- | --- |
| Rust整形・静的検査・単体/統合 | `cargo fmt --all --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo lint`、`cargo test --workspace` |
| 独自lint自体 | `cargo fmt --manifest-path tools/lint/Cargo.toml --all --check`、同manifestのclippy/test |
| 仕様モデル | `bash scripts/quint-gate.sh`および既存のITF対応テスト |
| カバレッジ | `bash scripts/coverage.sh --base origin/main`。90%床・既存相対ゲートを維持 |
| 配布同期 | `bun scripts/aidlc-sync.ts --check`とCIに列挙されたBun回帰テスト |
| 依存監査 | `cargo audit`、`cargo audit --file tools/lint/Cargo.lock` |
| 統合条件 | 対象コミットのCI全ジョブ、未解決レビュー、mainとの競合を確認 |

CIの実行条件は`.github/workflows/ci.yml`を正本とする。`audit`は集約の必須対象に含まれなくても、今回の全ジョブ成功条件には含める。イベントにより非適用の検査は、その条件とともに記録し、成功に書き換えない。

B1はU1・U2の双方が完了するまで統合しない。途中で失敗するテストをmainへ入れたり、検査を弱めて分割を成立させたりしない。B2/B3も直前の統合結果を基準にする。具体的なブランチ・作業ツリーは実行時のmainと作業記録を確認して用意する。

## 全体検証と切替

4単位の実装後にBuild and Testで全体を検証し、Deployment Executionで本リポジトリの実地確認と切替を行う。

- [ ] `target/release/aidlc`を実体に、実際のClaudeとフック・人の応答でbugfix intentを開始から完了まで通す。
- [ ] 本リポジトリで同バイナリのdoctorが成功する。
- [ ] 対象コミットのCI全ジョブ成功を確認する。
- [ ] 対象コミット・バイナリと対応する初回の安定タグ、ホスト参照先と復帰先を確認する。
- [ ] 検証済みホストへ切り替え、ホストと開発版を使い分ける。

ローカル・リモートのタグ一覧は計画時点で空だった。開発中は現在の配布済みホストを使い、まだ存在しないネイティブ安定版があるとは扱わない。タグ名と実体は切替の証拠が揃った時点で確定する。
